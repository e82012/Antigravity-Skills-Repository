# Markdown Metadata 規範（完整版）

> 主準則 §10.1 只列格式與三條要點，本檔補齊判準、邊界情況與例外。
> 每次**新建或修改 `.md` 檔案**時，於文件**最底部**維護 metadata 區塊。

## 格式

```markdown
---
**最後更新**: YYYY-MM-DD
**維護者**: 開發團隊
**文件版本**: vX.Y
**變更記錄**（里程碑，最多 5 條）:
- vX.0 (YYYY-MM-DD): 這一版讀者該知道的實質差異
```

## 版本與日期

- `最後更新` **每次修改都更新**
- `文件版本` **只跟里程碑走**：升 vX.0 時才進版，小改不動版本號——這樣文件版本永遠查得到對應的變更記錄條目，不會出現「標 v7.1、記錄裡卻沒有 v7.1」的懸空版本
- 新建文件從 `v1.0` 開始

## 變更記錄只寫里程碑，不寫流水帳

變更記錄是給讀者看「這份文件經歷過哪幾個重要階段」，不是改動日誌——逐次修改的軌跡 git log 已經有了，不需要在文件裡重抄一遍。

- ✅ 只有**升到 vX.0 的里程碑改動**才新增一條：結構重整、規則新增／刪除、結論翻案、適用範圍改變
- ❌ 小改**不新增條目**，只更新 `最後更新`：錯字、排版、補一句說明、換連結、數字微調
- 記錄上限 **5 條**，超過時把最舊的幾條壓成一條（例：`- v1.0–v3.0 (2026-01～05): 初版建立至規則體系成形`）
- 一條寫一行，寫「這版之後有什麼不同」，不寫「我改了哪幾行」

判斷準則：**半年後讀者回頭看這條，還會覺得需要知道嗎？** 不會就別記。

## 例外：訂正型小改要記，因為沒有 git 兜底

「逐次軌跡交給 git log」有前提——**檔案得在 git 裡**。不在任何 repo 內的文件（常見如 `.claude/`、`.local/`、`tmp/` 底下者，或工作區根本不受版控），改掉就沒有任何地方留得住舊版。**動筆前先確認手上這個檔在不在 repo 內**（`git -C <路徑> rev-parse --show-toplevel`），不要憑目錄名假設。

所以小改裡要再分出一類：**更正文件裡寫錯的事實**（路徑指向不存在的位置、數字錯誤、陳述與現況不符）。這類不升版本號，但要留一條，格式為 `- 訂正 (YYYY-MM-DD): 從 X 更正為 Y`。

- ✅ 記：「參考知識路徑由外部絕對路徑更正為 `resources/`（隨技能打包）」——讀者若照舊版做過事，需要知道那是錯的
- ❌ 不記：錯字、排版、換句話說——內容自明，丟了不影響任何人

理由是「無 git 可回溯」，不是「讀者想看歷程」。檔案若在 repo 內，這條例外不適用。

「這次為什麼這樣改」「原本以為是什麼」屬對話層說明，講給使用者聽即可，不寫進變更記錄。

---
**最後更新**: 2026-07-23
**維護者**: 開發團隊
**文件版本**: v1.0
**變更記錄**（里程碑，最多 5 條）:
- v1.0 (2026-07-23): 首版，自主準則 §10.1 抽出的完整版，補齊版本判準、里程碑認定與無 git 兜底時的訂正例外
