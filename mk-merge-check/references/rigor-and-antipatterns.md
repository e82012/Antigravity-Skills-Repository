# 嚴謹比對規則與反模式

> **動筆寫任何比對工具前必讀。** 整併差異檢查最大的失敗來源不是「漏比」，而是「用了會給假訊號的淺層比對法，卻以為驗過了」。本檔列出禁用的淺層法與對應正解。呼應全域 §1.3。

## 核心原則

**判定「相同／不同」的依據，必須是語意層級的逐項對照；任何把內容壓縮成單一數字（數量、長度、雜湊以外的計數）再比較的做法，都是淺層代理指標，一律禁用。**

一句話自問：**這個比對法，會不會在「明明不一樣」時回報「一樣」，或在「其實一樣」時回報「不一樣」？** 只要任一情況成立，就是瑕疵法。

## 禁用的淺層比對法（會給假訊號）

### 程式碼比對

| 禁用法 | 為何是瑕疵 |
|--------|-----------|
| 比行數 / 檔案大小 / 字元數 | 行數相同邏輯可完全不同；重排、換行、註解都會變動數字卻不動邏輯。反向也成立：等價重構行數本來就不同。 |
| 比 `grep -c` 某關鍵字出現次數 | 出現次數一樣不代表用在同樣的地方、同樣的條件。 |
| 只比方法**數量**、欄位**數量** | 數量對得上是必要非充分；名稱、型別、順序、語意都可能不同。 |
| 檔案層級 `diff` 就下結論 | 兩邊方法名不同、結構不同（策略模式 vs 內嵌），整檔 diff 會滿江紅，但輸出可能完全一致——會把等價重構誤判成重大差異。 |
| 比 MD5／雜湊判斷「是否相同」 | 只能答「逐字元是否全等」，答不了「邏輯是否等價」；空白一改就不同，等價重構永遠 mismatch。 |

### 輸出結果比對

| 禁用法 | 為何是瑕疵 |
|--------|-----------|
| 比回傳筆數 / 陣列長度 | 筆數一樣，每筆的值可能全錯。 |
| 比 JSON 字串長度 / 字元數 | 長度巧合相等極常見；且 key 順序、浮點格式、空白都影響長度卻無關正確性。 |
| 直接 `==` 比對未正規化的 JSON 字串 | key 順序不同、浮點 `1.0` vs `1`、`null` vs 缺鍵、時間戳，會讓「其實一致」被判成「不同」，逼出一堆假差異淹沒真差異。 |
| 只比第一筆 / 抽樣幾筆 | 差異常出現在邊界（最後一頁、金額最大筆、跨月）。抽樣會漏。 |
| 只比 HTTP 狀態碼 / `success` 旗標 | 兩邊都回 200／true，資料內容可以天差地別。 |

## 正解

### 程式碼：語意／結構層級

1. **以路由 URI 錨定**，追到兩邊各自「實際執行的那一行」（§1.3 三步查證），比的是**同一條呼叫鏈**，不是同名檔案。
2. **逐方法、逐邏輯單元對照**：
   - 查詢：實際的表、join 關係、where 條件、group by／having、order by、limit。
   - 運算：參與計算的欄位、加總／彙總公式、四捨五入策略、幣別／單位換算。
   - 分支：條件邊界、查無資料的處置、預設值（如日期預設本週）。
   - 回應：欄位集合、巢狀結構、型別、命名。
3. **差異要能對應到具體行為**：說得出「這行差異在什麼輸入下會造成什麼輸出不同」，說不出就不是有效差異（可能只是等價重構）。
4. 可用 AST／語法感知工具輔助，但結論以人工逐邏輯確認為準。

### 輸出：正規化後逐鍵逐值深比對

1. **先正規化，再比對**（兩邊套完全相同的正規化）：
   - 遞迴排序物件的 key。
   - 浮點統一精度（如固定小數 6 位或依業務精度四捨五入），或以容差比較。
   - 統一數字型別（`"1"`、`1`、`1.0` 視需要對齊）。
   - `null` 與缺鍵的對待一致化。
   - 遮罩「本來就該不同」的欄位（自增 ID、建立時間、request id），並在報告中列出被遮罩的欄位清單，不要默默吃掉。
2. **逐鍵逐值遞迴深比對**，輸出結構化 diff：哪個 path、左值、右值。**全量比對，不抽樣**。
3. **多組輸入**：至少涵蓋正常區間 ＋ 邊界（跨月、無資料、單筆、大量、金額極值），不是只跑一組就收。
4. **報告差異要落到 path 級**：例如 `data[3].winLose: MK=-1200.5 / 原版=-1200.0`，不是「輸出不一樣」。

## 收斂判準

- **通過**：所有輸入下，正規化後**逐鍵逐值全等**（或落在明訂容差內），且被遮罩欄位清單已列明並經確認合理，且**兩側都是真實成功回應**（HTTP 200 / success=true），不是「兩邊同樣報錯」被算成一致——後者是假一致，等於沒驗到。判定「一致」前先確認兩側非錯誤狀態。
- **未過**：任一 path 出現非遮罩的值差異 → 進 severity 分級，實質差異進 Phase 4 修正。

## 自查清單（寫完比對工具後跑一遍）

- [ ] 動態驗證前，兩邊 `.env` 是否連**同一個 DB**（`DB_CONNECTION/HOST/PORT/DATABASE/USERNAME` 逐項相同）？不同 → 停，先對齊，否則測出的全是資料差異。
- [ ] 我的比對有沒有任何一步是「把內容變成一個數字再比大小／是否相等」？有 → 換掉。
- [ ] 兩邊正規化是不是「完全同一套」？只對一邊做正規化 = 製造假差異。
- [ ] 有沒有抽樣或只比前 N 筆？有 → 改全量。
- [ ] 遮罩了哪些欄位？清單有沒有寫進報告？
- [ ] 差異報告能不能指到具體 path＋左右值？不能 → 比對粒度不夠。
- [ ] 邊界輸入跑了沒（跨月、無資料、極值）？
- [ ] 判定「一致」的那些組，兩側是否都真的成功（非兩邊同樣報錯的假一致）？
