# 詞彙表 — 寫出好技能

「什麼樣的技能算好」的領域模型。技能存在是為了從隨機系統裡榨出確定性，根本德性是**可預測性**，底下每個詞都是它的一根槓桿。這是 [`SKILL.md`](SKILL.md) 揭露出來的參考文件。

詞彙依四個軸分組：**調用**（技能怎麼被搆到）、**資訊階層**（內容怎麼排）、**操舵**（代理執行期的行為怎麼被塑形）、**修剪**（怎麼保持精瘦）。每個**失敗模式**就放在能治它的那根槓桿旁邊，標記為 _失敗模式_。

任一定義中的**粗體詞**本身也在這份詞彙表裡，用標題找得到。

`_別這樣叫_` 列出的是刻意迴避的近義詞——它們會稀釋這個詞在技能裡累積起來的分散式定義。

---

## 可預測性 (Predictability)

技能讓代理每次都用同一種**方式**行動的程度——同一套流程，不是同一份輸出（腦力激盪技能就該「可預測地」發散：它的 token 每次不同，它的行為每次相同）。這是其他所有詞服務的根本德性；成本與可維護性是它的症狀，不是它的對手。

_別這樣叫_：一致性、穩定性、健壯性、輸出確定性

---

## 調用 (Invocation)

技能怎麼被搆到，以及這個選擇要付的兩種負載。

### 模型可調用 (Model-Invoked)

保留 `description` 欄位的技能，代理看得到、能自己觸發；人也照樣打得出它的名字——所以模型可調用永遠**包含**使用者可及性，不存在「只有模型能用」這種狀態。代價是每一輪都要付**上下文負載**。也因為有 description，**其他技能搆得到它**。內容全是**參考**的模型可調用技能，是共用參考的一種歸宿：多個技能需要的同一份參考，可以只存在這一處。

_別這樣叫_：能力、工具、function

### 使用者可調用 (User-Invoked)

`description` 被拿掉的技能——代理看不見，只有人打出名字才搆得到（模型可調用是「人＋代理」，這裡是「只有人」）。用代理可發現性換到零**上下文負載**。因為沒有 description，除了人以外沒有東西搆得到它：**別的技能也叫不動它**。

_別這樣叫_：流程、工作流、指令

### 描述 (Description)

技能給機器讀的觸發器，也是模型可調用技能被迫永遠載著的那一個**上下文指標**。它的存在與否**就是**調用軸本身：留著它，技能就是模型可調用（且可被其他技能調用）；刪掉它，技能就變成使用者可調用。模型可調用技能的**上下文負載**來源。

_別這樣叫_：frontmatter、摘要

### 上下文指標 (Context Pointer)

一個留在代理 context 裡的引用，指名某份不在 context 裡的材料，並編碼了「什麼時候該去搆它」的條件。**描述**是最上層的上下文指標（context window → 技能），指向被揭露檔案的指標是同一個物件往下一層。**決定代理何時搆、以及搆得多可靠的是它的措辭，不是它指向誰。** 必讀的材料掛在一個措辭很弱的指標後面，就是一個變異性 bug：先修措辭，修不動才把材料拉回內嵌。

_別這樣叫_：連結、引用、import

### 上下文負載 (Context Load)

模型可調用技能對 context window 施加的成本——它那行常駐的**描述**，同時花掉 token 與注意力。這是**使用者可調用**技能因為沒有描述而躲掉的東西，也是「不要再多切一個模型可調用技能」的煞車。

_別這樣叫_：token 成本、context 膨脹

### 認知負載 (Cognitive Load)

使用者可調用技能對**人**施加的成本——人得自己記住有哪些技能、什麼時候該用哪個（人就是那份索引）。這是模型可調用因為代理可發現而免掉的東西，也是「不要再多切一個使用者可調用技能」的煞車。**這不是一項該最小化的成本**：它是人保有主導權的價碼，也是某些技能該維持使用者可調用的理由。人的判斷有價值的地方就花它，沒價值的地方就免掉。

_別這樣叫_：人腦索引、負擔、額外開銷

### 路由技能 (Router Skill)

一個使用者可調用的技能，工作是指向你其他的使用者可調用技能——列出每一個以及何時該用——讓人只需要記住一個。它只能**提示，不能觸發**：使用者可調用技能沒有**描述**，所以除了人以外沒有東西叫得動它們。這是使用者可調用技能變多之後，治**認知負載**的解。

_別這樣叫_：派發器、選單、註冊表、索引

### 顆粒度 (Granularity)

你把技能切多細。切得越細就越花兩種負載其中之一：模型可調用技能越多，越花**上下文負載**（更多描述擠在 context 裡搶注意力）；使用者可調用技能越多，越花**認知負載**（人要記的越多）。兩種切法見 [`SKILL.md`](SKILL.md)「何時該拆」。反向也要小心：把序列合併回去，等於把每一步的**後續步驟**都攤在後面的視野裡，反而招來過早完成。

_別這樣叫_：切塊、模組化

## 資訊階層 (Information Hierarchy)

技能的內容怎麼排，以及每一塊落在階梯的哪一層。

### 資訊階層 (Information Hierarchy)

技能內容依「代理多急著要」排出的**單一階梯**，由兩刀切出：在檔內或在指標後、是步驟或是參考。三層：

- **步驟**——檔內，最上層
- **參考**（檔內）——次要
- **參考**（被揭露）——在**上下文指標**後面

沒有步驟的技能只用下面兩層——經常是一組合法的扁平同級項（例如一次審查的每條規則都在同一層），這是正常編排，不是壞味道。階層與調用方式互相獨立。當技能**有**步驟時，本該被揭露卻留在檔內的參考會把步驟埋掉，讓「代理會不會照做」變成擲硬幣——這是變異性槓桿，不只是可讀性問題。

_別這樣叫_：結構、組織、排版

### 步驟 (Steps)

代理要執行的有序動作。技能若有步驟，步驟就是內容的最上層，也是它值得佔住 `SKILL.md` 的理由。不是每個技能都有步驟：可以全是步驟、全是**參考**、或兩者都有，與調用方式無關。每個步驟都結束在一個**完成判準**上——清楚的，或模糊的。

_別這樣叫_：工作流、指示、編排

### 參考 (Reference)

代理按需查閱的材料——定義、事實、參數、範例、條件式指示。技能有**步驟**時它次要；技能沒步驟時它就是全部內容；也可能完全活在技能系統之外——見**外部參考**。透過**上下文指標**搆到，是**漸進揭露**的頭號候選。

_別這樣叫_：輔助材料、文件、背景知識

### 外部參考 (External Reference)

活在技能系統之外的**參考**——一個普通檔案，沒有**描述**、沒有**步驟**、不可被調用——任何技能都能指過去。這是「共用但不需要自己觸發」的參考的歸宿，也是**兩個使用者可調用技能唯一能共用的家**（兩邊都沒有描述，誰也叫不動誰）。

> 本技能組的實例：`diff-review` 的 Standards 軸指向既有的 `code-review` 技能當外部參考，不重抄一份檢查表。

_別這樣叫_：文檔、資源、知識庫

### 漸進揭露 (Progressive Disclosure)

把**參考**往階梯下方搬——移出 `SKILL.md`、放到**上下文指標**後面——好讓頂層維持可讀。它主要不是 token 優化，而是**保護資訊階層**的手段。授權它的是**分支**：只有部分分支要的就揭露，每條路徑都要的就內嵌。必讀材料的指標若觸發不可靠，先磨措辭，磨不動才拉回內嵌。

_別這樣叫_：延遲載入、切塊

### 共置 (Co-location)

把代理「同一時間會需要」的材料放在同一個位置——一個概念的定義、規則、注意事項收在同一個標題底下，不散在整份檔案裡——讀到其中一段就會順帶讀到鄰居。它是**資訊階層**的檔內搭檔：階層排「放多下面」，共置決定「旁邊擺什麼」。與**重複**不同：重複是同一個意思出現在兩處，散置是同一個意思被拆碎在多處。

_別這樣叫_：分組、聚類、內聚

### 膨脹 (Sprawl)

_失敗模式。_ 技能單純就是太長——`SKILL.md` 行數過多——與那些行是否過期或重複無關。就算全部還活著、全部不重複，一樣可能膨脹。它的代價是可讀性（代理要涉水更久才能動手，注意力被稀釋）、可維護性（多一行就多一行要維持**相關性**）與 token。解法是**資訊階層**。與**沉積**（長度來自陳舊堆積）和**重複**（長度來自意思重覆）不同——膨脹就是長度本身。

_別這樣叫_：肥大、篇幅、囉嗦

## 操舵 (Steering)

把代理執行期的行為推向**可預測性**的槓桿。

### 分支 (Branch)

技能被調用的一種獨立方式——它處理的一個情境——使不同次執行走過技能的不同路徑。步驟多的技能可能帶很多分支；線性的技能一個也沒有。

_別這樣叫_：路徑、case、分岔

### 引導詞 (Leading Word)

一個緊湊的概念——也叫 _Leitwort_——已經活在模型的預訓練裡，代理執行技能時會用它來思考。它用最少的 token 編碼一條行為原則，因為它徵用的是模型本來就有的先驗（例如：*紅燈*、*曳光彈*、*接縫*、*戰爭迷霧*、*近側發展區*）。**當成一個詞反覆出現，而不是當成一句話**，它會在整份技能裡累積出分散式定義，錨定一整區行為。自創詞在定義夠清楚時也能用，但自創詞徵不到任何先驗——你會用定義的 token 去付一個預訓練詞本來免費給你的東西。先找現成的詞。

它替**可預測性**服務兩次。在本文錨定**執行**——概念每次出現，代理都伸手拿同一套行為；在扁平參考裡，它把注意力聚焦到「該找哪一類東西」，每次執行都徵召到對的檢查。在**描述**裡錨定**觸發**——而且不限於技能內部：當同一個詞同時活在你的 prompt、文件與程式碼裡，代理會把這套共同語言連到技能上，觸發得更可靠。**用你真正想叫這個技能時會講出來的那些詞去寫描述。**

_別這樣叫_：關鍵字、術語、母題

### 完成判準 (Completion Criterion)

告訴代理「這一段工作做完了」的條件——它拿來對照的標的。兩個性質讓它成為槓桿，而不只是品質形容：

- **清晰度**（代理分得出做完與沒做完嗎？）抵抗**過早完成**。模糊的邊界（「達成共識」）讓代理可以宣告完成然後滑向下一步。這一軸需要有**步驟**才咬得住，因為過早完成是「步驟之間」的失敗。
- **要求度**（它要求多少）決定**功課**的厚度——「每一個被改到的模型都交代過」逼出扎實的挖掘，「產出一份異動清單」不會。這一軸**不受步驟限制**：它也能綁住一整片扁平參考，這就是沒有步驟的技能仍然扛得住窮盡度門檻的方式（「每一條規則都套用過」）。

最強的判準同時可檢核且窮盡。

_別這樣叫_：完成條件、退出條件、停止規則

### 功課 (Legwork)

代理在**單一步驟內**於幕後做的工作——讀檔、探索程式碼、動手改、自己挖出需要的東西，而不是丟回去問使用者。它活在步驟結構之下：從不寫成獨立步驟，潛伏在措辭裡，由代理而非技能控制。它是**後續步驟**跨步拉力的「步驟內」對照物。**引導詞**（全面、毫不留情）或要求窮盡的**完成判準**會把它拉高——包括把要求度施加在扁平參考上，那正是「一份全是參考的技能仍會覆蓋每一層」的驅動力。它變薄的原因有二：要求度缺席，或**過早完成**把步驟切斷。

_別這樣叫_：範圍、投入、細心度、覆蓋率

### 後續步驟 (Post-Completion Steps)

當前步驟之後的那些**步驟**。它們一旦可見，就會把代理往前拉向**過早完成**——看得越多，拉力越強。防守方式是把序列切成兩段，讓它們看不見。

_別這樣叫_：視野、戰爭迷霧、前瞻

### 過早完成 (Premature Completion)

_失敗模式。_ 當前步驟還沒真的完成就結束它，因為代理的注意力滑到「做完了」而不是工作本身。這是**步驟之間**的失敗：沒有步驟的技能提早收工不叫過早完成，那叫要求度沒被滿足導致的**功課**過薄。

它是兩股力量的拔河：可見的**後續步驟**（向前的拉力）對上**完成判準**的清晰度（阻力——尖銳可檢核的門檻撐得住，模糊的會讓步）。**模糊是必要條件**：門檻夠尖銳時，後面看得見幾步都撐得住。所以兩根槓桿要照順序用：**先磨利門檻**（局部、便宜）；只有在判準真的無法再精確**而且**你確實觀察到搶快時，才**把後面的步驟藏起來**——而且藏只在真正的 context 邊界上才有效（使用者可調用的交棒、或 subagent 派發；行內的模型可調用呼叫會把後續步驟留在 context 裡，什麼也沒清掉）。

_別這樣叫_：提早收斂、搶快、抄近路

### 否定式提示 (Negation)

_失敗模式。_ 用禁令操舵——告訴代理**不要**做什麼——反而把被禁的行為拖進 context，讓它**更**容易被想起，不是更少。「別想大象」，於是滿場都是大象；「絕對不要寫冗長註解」，於是冗長就是代理剛剛讀到的模式。否定是個弱修飾詞，會被強烈激活的概念輾過去，禁令有一半被讀成「去做那件事」的指示。它的**引導詞**就是那頭「大象」：禁令把什麼叫進了場。解法：**正面陳述**——描述目標行為（「註解寫成一行」），讓被禁的那個從頭到尾沒被講出來。禁令只在「這個行為無法正面表述」時才有位置，即使那時也要配上正面標的。

_別這樣叫_：反諷反彈、don't-prompting、粉紅大象

## 修剪 (Pruning)

保持技能精瘦——每帖解藥都配著它治的那個病。

### 單一真實來源 (Single Source of Truth)

每個意思都恰好活在一個權威位置的理想狀態，於是改技能的行為就是改一個地方。**重複**是它的違反。

_別這樣叫_：歸宿、正典位置

### 重複 (Duplication)

_失敗模式。_ 同一個意思被給了不只一個**單一真實來源**。它花維護成本（改一處就得改其他處）、花 token，還會膨脹份量——重述一個意思，等於把它在階梯上的權重灌得比實際位階高。它是**引導詞**的意外反面：引導詞刻意重複「同一個詞」來抬高注意力，從不重複「同一個意思」。

_別這樣叫_：重述、冗餘

### 相關性 (Relevance)

某一行是否還跟技能要做的事有關——決定留什麼的透鏡。一行失去相關性的方式有二：從來就跟任務無關（純鋪陳，或一個該被揭露的**分支**），或是過期了（它描述的行為或世界已經變了）。技能越短越容易維持相關，因為每一行的檢查成本更低。與 **no-op** 不同：相關性問「這行跟任務有沒有關」，不是「這行有沒有改變行為」。

_別這樣叫_：承重、過時、新鮮度

### 沉積 (Sediment)

_失敗模式。_ 舊內容一層層積在技能裡沒人清，因為新增感覺安全、刪除感覺危險——於是陳舊與不相關的行不斷累積，你得往下鑽開它們才找得到還活著的東西。任何沒有修剪紀律的技能的預設下場；它是**相關性**的緩慢侵蝕，相對於**重複**的意思重覆。

_別這樣叫_：堆積、肥大、殘渣、腐化

### No-Op

_失敗模式。_ 一條什麼也沒改變的指示，因為模型預設就會這麼做——你付了負載，卻只是在告訴代理它本來就會做的事。測試方法：**這行相對於預設行為，有改變任何東西嗎？** 一行可以完全**相關**卻仍然是 no-op。讓**引導詞**免費的那些先驗，也正是讓 no-op 一文不值的東西。

引導詞是一項**技術**，No-Op 是對一行的**判決**，兩者會交叉：弱到打不贏預設的引導詞就是 no-op（代理本來就算細心，你還寫「請仔細」），解法是換一個過得了判決的更強的詞（「毫不留情」），不是換技術。所以 no-op 測試同時也是在替引導詞打分。**這是相對於模型、不是相對於讀者**：兩個人爭論某行是不是 no-op，其實是在爭論預設行為是什麼，該用「跑一次技能」來裁決，不是用辯論。

_別這樣叫_：冗餘指示、重申常識、贅述
