# 帶文件的拷問

跟 `grill-me` 一樣的拷問，差別是**有狀態**：它會把拷問過程中學到的東西留在倉庫裡。有程式碼倉庫時從這裡開始。

## 步驟

1. **先讀現況**。讀 `CONTEXT.md`（若存在）與相關 ADR，建立這一區的心智模型。已經有定義的詞就照用，不要另起爐灶。**完成判準**：你能用專案既有的詞彙複述一次這次要動的東西是什麼。

2. **跑 `grilling`**。過程中每當出現以下三種訊號，就地觸發 `domain-language` 處理，不要留到最後：
   - 我用了一個 `CONTEXT.md` 裡沒有的詞
   - 同一個詞在對話裡指了兩件不同的事
   - 出現一個難以回頭的決策（選型、資料模型、對外介面、相容性承諾）

3. **收尾寫入**。拷問結束後，把這一輪的產物落地：
   - 新詞與被磨利的定義 → 寫進 `CONTEXT.md`
   - 難以回頭的決策 → 一則 ADR，寫下脈絡、決策、後果
   - **完成判準**：這次對話裡出現過的每一個新詞，都在 `CONTEXT.md` 找得到，或被明確判定為不值得收錄。

## 為什麼值得

共同語言不只是省字。它讓變數、函式與檔案的命名一致，讓代理更容易在程式碼裡導航，也讓代理花在「猜你在說什麼」的 token 變少。

一句對照，看得出差別：

- **之前**：「課程裡某個章節底下的一堂課被『變成真的』（也就是在檔案系統裡拿到位置）的時候會出問題」
- **之後**：「materialization cascade 有問題」
