# 切成曳光彈工單 (To Tickets)

**曳光彈**：一張票要打穿整個系統的一條薄切片——從介面到資料層——而不是做完某一層。曳光彈落地的當下你就看得到它打到哪，可以據此修正下一發。切成水平層（「先做完所有 model」）看不到彈道，等到組起來才發現方向錯了。

## 步驟

1. **讀設定與規格**。讀 `docs/agents/flow-config.md` 與要切的規格／對話。

2. **切票**。每張票必須滿足三個條件，缺一就不是一張票：
   - **薄**：一個 session 做得完（含測試與審查）
   - **可驗**：有自己的驗收條件，做完當下驗得出來
   - **穿透**：走完一條端到端的路徑，不是只做完某一層

3. **標明阻擋邊**。每張票列出「被哪幾張票擋住」。這是切票唯一需要動腦的部分——沒有阻擋關係就代表可以平行開工。
   - 本地檔案模式：一張票一個檔案，放 `tmp/{功能名}/tickets/NN-標題.md`，票裡用 `阻擋：#02, #03` 標明，人工照順序做
   - 真實追蹤系統模式：阻擋關係寫成原生的 blocking link，阻擋項清完的票就可以直接被撈起來做

4. **票的格式**：

   ```markdown
   # NN — <標題>

   **阻擋**：#02（沒有它就沒有資料表可寫）
   **接縫**：`OrderService::settle()`

   ## 做什麼
   一段話講完這顆曳光彈打穿哪條路徑。

   ## 驗收條件
   - [ ] 可檢核的條件，一條一行
   ```

5. **回報彈道**。把票的順序與阻擋圖攤給使用者看過，等確認再發佈。

## 完成判準

規格裡的每一條「範圍內」條目，都被至少一張票覆蓋；每張票都指得出自己的接縫與驗收條件；阻擋圖裡沒有循環。

## Context 衛生

從 `grill-with-docs` 到 `to-tickets` 應該待在**同一個沒有中斷的 context window** 裡——不要在切完票之前 compact 或 clear，讓拷問、規格、工單建立在同一份思考上。切完票之後，**每張票各自開一個乾淨的 session** 跑 `implement`。
