# 工程流程技能組的設計依據

本組技能改編自 [mattpocock/skills](https://github.com/mattpocock/skills)（MIT License）。這份文件記錄「學了什麼、為什麼值得學、刻意不學什麼」。

## 學到的九個手法

### 1. 兩種調用模式，兩種可計價的負載

`disable-model-invocation: true` 把「要不要讓模型看到這個技能」變成一個明碼標價的取捨：保留 `description` → 代理可自主觸發、其他技能也叫得動，代價是那行描述每一輪都佔 context；拿掉 → 上下文負載歸零，但人得自己記得它存在。

過去技能全部預設模型可調用，等於無條件付這筆帳。分開之後，只有真的需要被代理或被其他技能搆到的才付。

### 2. 原語 + 包裝層

`grilling` 是模型可調用的原語（8 行），`grill-me` 與 `grill-with-docs` 是使用者可調用的包裝層，各自一句「跑一次 grilling」加上自己的差異。拷問的行為只有一個真實來源，改一次全部生效。

### 3. 路由技能

使用者可調用技能一多就記不住，用一個技能當索引解掉。而且它誠實標明自己**只能提示、不能觸發**——因為被指向的那些沒有 description。

### 4. 引導詞 (Leading Word)

用模型預訓練裡已存在的壓縮概念當錨：*緊（tight）*、*紅燈*、*曳光彈*、*接縫*、*戰爭迷霧*。一個詞召回一整區行為，比寫三句話便宜、而且更準。

它服務兩件事：在本文錨定執行（同一個詞每次拿到同一套行為），在描述裡錨定觸發（同一個詞活在你的 prompt 與程式碼裡，代理連得起來）。

### 5. 完成判準是槓桿，不是形容詞

每個步驟結束在一個**可檢核**（分得出做完與沒做完）且必要時**窮盡**（「每一個都交代過」而非「產出一份清單」）的條件上。

最強的示範：`diagnosing-bugs` 階段 1 要求「貼出你**已經跑過至少一次**的那一行指令與它的輸出」。這個判準沒辦法用嘴唬過去。

### 6. 失敗模式被命名，且與解藥共置

過早完成、重複、沉積、膨脹、no-op、否定式提示——每個失敗模式就寫在能治它的槓桿旁邊。等於把「診斷技能為什麼不聽話」的能力也做進方法論裡。

### 7. 否定式提示是反模式

「別想大象」把大象叫進場。否定是弱修飾詞，會被強烈激活的概念輾過去。改成正面陳述目標行為，讓被禁的那個從頭到尾沒被講出來；禁令只留給無法正面表述的硬護欄，而且要配上「那該做什麼」。

### 8. 回饋迴路優先於推理

除錯技能明講「這一階段就是整個技能，其餘都是機械操作」，並且沒有紅得起來的迴路就**禁止**進入假設階段。這把最常見的除錯失敗（先腦補理論再找證據支持它）從流程層擋掉。

### 9. 雙軸平行審查

規範軸與規格軸用兩個 sub-agent 平行跑，理由是**避免 context 互相污染**——同一個 agent 依序審兩軸，第一軸的結論會替第二軸定調。乾淨地實作錯功能，跟髒亂地實作對功能，是兩件不同的事，混排會把這件事洗掉。

## 刻意不學的

| 原作做法 | 本組改法 | 理由 |
|---------|---------|------|
| 技能名帶個人品牌（`ask-matt`、`setup-matt-pocock-skills`） | `skill-map`、`setup-flow` | 技能名就是觸發語，該描述功能 |
| 產物落 `.scratch/` | 落 `tmp/{任務名}/`、`e2e/{任務名}/` | 對齊全局準則 §5 的檔案放置慣例 |
| 規範軸內建 Fowler 壞味道清單 | `diff-review` 引用既有 `code-review` 技能 | 本倉庫已有一份判斷準則，重抄就是**重複** |
| 全英文 | 全繁體中文＋台灣用語，觸發語含中文 | 對齊全局準則的語言政策；使用者用中文下指令，描述只放英文術語觸發不到 |

## 未查證事項

⚠️ `disable-model-invocation` 確認是 Claude Code 支援的 frontmatter 欄位，**Antigravity 是否支援未經查證**。因此本組所有使用者可調用技能的 `description` 都寫成「人讀得懂、同時也能當觸發語」——欄位若被忽略，行為仍然正確，只是多付一份上下文負載。
