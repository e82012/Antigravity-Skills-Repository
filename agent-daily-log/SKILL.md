# Agent 使用日誌 (Daily Log Lite)

協助使用者建立、填寫或更新「Agent 使用日誌」，格式固定如 `assets/template.md`，用來追蹤每日任務、平行處理決策、模型選擇案例與學習心得。

## 何時使用

- 使用者要求建立/填寫今日（或指定日期）的 agent 使用日誌
- 使用者想記錄今天完成了哪些任務、花了多少時間、用了哪個模型
- 使用者想記錄「平行處理」相關決策（哪些任務同時做、哪些刻意不平行）
- 使用者想記錄模型選擇的決策案例（為什麼選 Sonnet 或 Haiku）
- 使用者想做每日學習總結或規劃明日工作

## 工作流程

1. **取得日期**：若使用者未指定日期，預設使用今天日期（YYYY-MM-DD 格式）。
2. **複製範本**：以 `assets/template.md` 為基底，將 `{{DATE}}` 替換成實際日期。
3. **蒐集內容**：
   - 從目前對話歷史中，盡量自動萃取以下資訊，減少使用者重複輸入：
     - 今日完成的任務、各自花費時間、使用的模型
     - 是否有平行執行的任務組合，以及判斷理由
     - 模型選擇的決策案例（任務類型、關鍵字、決策、理由、結果）
     - 學到的經驗、是否更新了任何規範文件
   - 若資訊不足以判斷，直接詢問使用者，避免空白亂填；找不到的欄位保留範本中的提示文字（如 `[任務描述]`）或填寫「本次無」。
   - 「⚡ 平行處理記錄」三個子區塊（平行執行 / 刻意不平行 / 未考慮平行）若當天無相關決策，依範本指示填「本次無」，不要留空方括號。
4. **產出檔案**：使用 `create_file` 在 `/mnt/user-data/outputs/` 建立 Markdown 檔案，檔名建議為 `agent-log-{{DATE}}.md`（例如 `agent-log-2026-06-30.md`）。
5. **呈現給使用者**：呼叫 `present_files` 讓使用者下載/檢視。

## 補寫或更新既有日誌

若使用者提供已存在的日誌檔案要求補充或修改：
- 先 `view` 該檔案內容
- 使用 `str_replace` 針對需要更新的區塊做精準編輯，避免整篇重寫導致格式跑掉
- 維持原本的標題層級與 emoji 符號不變

## 格式注意事項

- 嚴格保留範本的章節順序與標題：今日完成 → 平行處理記錄 → 決策案例 → 今日學習 → 明日計畫
- 「決策案例」若當天有多個，依序編號為 `#1`, `#2`...
- 「驗證錨點」欄位若無對應的 git commit 或 PR，填寫 `N/A`
- 保持 Markdown 純文字格式，不要額外加入表格或項目符號以外的排版

## 範本檔案

完整空白範本位於 `assets/template.md`，所有欄位語意可參考其中的中文括號提示文字。
